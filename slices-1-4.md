# Слайс 1 — один вызов

## Что в коде

```ts
const client = new Anthropic();
const res = await client.messages.create({
  model: "claude-sonnet-5",
  max_tokens: 2048,
  system: SYSTEM,
  messages: [{ role: "user", content: `Company: ${company}` }],
});
```

**`new Anthropic()`** сам достаёт `ANTHROPIC_API_KEY` из окружения. Отсюда `.env` и `.gitignore`. И отсюда же твой 401: `dotenv` **не перезаписывает** переменные, которые уже есть в окружении, а у тебя в профиле торчал старый ключ. Лечится `dotenv.config({ override: true })`. Принцип шире одного бага: **проект должен зависеть от того, что лежит рядом с ним, а не от невидимого состояния снаружи.**

**`system` — отдельный top-level параметр**, не элемент массива. Туда идёт то, что верно для каждого вызова: роль, правила, формат. В `messages` — то, что относится к этому ходу. Массив, потому что туда ляжет вся история: user, assistant, user, assistant.

**`max_tokens` — это бронь, а не пожелание.** В окно должно поместиться input + max_tokens вместе, место резервируется заранее. Поэтому промпт 195k при окне 200k с `max_tokens: 8000` отклоняется, хотя сам промпт влезает свободно.

И это же объясняет, почему у тебя ответ четыре раза подряд обрывался на середине слова: модель не «укладывается покороче», она пишет как писала и **молча замолкает** на потолке. Ни ошибки, ни предупреждения. Поэтому:

```ts
if (res.stop_reason === "max_tokens") console.warn("!! TRUNCATED");
```

**`content` — массив блоков, а не строка.** Сейчас блок один, текстовый. В слайсе 2 станет понятно зачем.

**`res.usage`** — реальный счёт от API: `input_tokens`, `output_tokens`.

## Что этот слайс показал

С правилом `If you are not certain, write UNKNOWN. Never guess.` модель честно проставила UNKNOWN в основателях и вакансиях. Честно и **бесполезно**.

Убираешь правило — получаешь уверенное досье, которое **врёт точечно**. Zeno Rocha назван верно, а работодатель до Resend подменён: сказано Codecov, на самом деле WorkOS. Открытые вакансии — придуманы две несуществующие («frontend engineer», «DevRel») и пропущена настоящая (Product Engineer).

Вывод, который ты получил не с моих слов:

> Опасная галлюцинация — не та, что выглядит глупо. Та, что выглядит правильно.
> И **промптом знание не добывается**: никакая формулировка не сделает модель осведомлённой о том, чего она не знает.

## Твои числа

```
input   84 × $2/M   = $0.00017
output 1707 × $10/M = $0.01707     ← 99% счёта
итого                 $0.01724
```

И отдельный урок, который ты поставил случайно: **ты убрал строку из system prompt, вход похудел на 26 токенов, а счёт вырос.** На входе сэкономил $0.000052, на выходе доплатил $0.00019 — проиграл вчетверо, потому что ответ стал длиннее.

> Экономия на промпте — театр. Деньги живут в выходе.

## Почему output дороже в 3–5 раз

Не «так в прайсе». Механизм:

Промпт известен целиком, поэтому внутреннее состояние всех его токенов считается **за один параллельный проход** — одна операция на всю простыню. Выход рождается по одному токену, и каждый требует **полного прохода** через модель: сколько токенов, столько проходов.

Будущее нельзя посчитать заранее, прошлое можно разом. Отсюда же вообще возможен streaming: раз токены рождаются по одному, их можно отдавать по одному.

# Слайс 2 — tool use

## Что в коде

```ts
const tools: Anthropic.Tool[] = [{
  name: "fetch_url",
  description: "Fetch a web page and return its visible text...",
  input_schema: {
    type: "object",
    properties: { url: { type: "string" } },
    required: ["url"],
  },
}];
```

## Петля, по шагам

1. Отправляешь `system + tools + messages`.
2. Модель возвращает ответ. Смотришь `stop_reason`.
3. Если `"tool_use"` — в `content` лежит блок `{type:"tool_use", id, name, input}`. Это **намерение**, не вызов.
4. Кладёшь весь `res.content` в `messages` как сообщение ассистента.
5. Исполняешь сам: идёшь в интернет, чистишь HTML.
6. Кладёшь результат обратно **как user-сообщение** с блоками `{type:"tool_result", tool_use_id, content}`. `tool_use_id` обязан совпадать с тем `id`.
7. Вызываешь модель снова. Возврат к шагу 2.
8. Если `stop_reason` не `"tool_use"` — модель закончила, печатаешь текст.

**Модель не вызывает ничего.** У неё нет рук. Руки — твой код. Это не техническая деталь, а основа безопасности: раз исполняешь ты, ты можешь проверить права. Модель просит `delete_user` — твой executor решает, можно ли **этой** сессии.

## Вот зачем `content` был массивом

Теперь приезжает `[{type:"text"}, {type:"tool_use"}]`. Модель одновременно рассуждает и просит инструмент, иногда несколько сразу. Фильтр по `type`, который в слайсе 1 выглядел лишним, оказался обязательным.

## description — это промпт, а не документация

Единственное, по чему модель решает, звать инструмент. Ты написал туда «USE IT», «your memory is stale», и что делать при ошибке — и это сработало. Пиши как инструкцию толковому незнакомцу: что делает, когда применять, **когда не применять**.

## Ошибки уходят модели, а не в исключение

```ts
if (!r.ok) return `ERROR: HTTP ${r.status} for ${url}`;
```

Модель читает эту строку и пробует другой url. Бросил бы исключение — агент умер бы на первой битой ссылке, потеряв всю оплаченную работу. **Ошибка инструмента — нормальные данные для модели, а не авария для программы.**

## MAX_STEPS

Не перестраховка. Агент, у которого инструмент стабильно падает, крутится, пока не кончатся деньги. Нужны оба потолка: по шагам и по бюджету. И логируй причину остановки — при разборе смотришь на неё первой.

## Твои числа

```
[step 1] in    712
[step 2] in 10589
[step 3] in 18175
[step 4] in 19054
[step 5] in 20714     ← весь разговор
total in: 69244    out: 2677    $0.16526
```

К пятому шагу контекст — 20 714 токенов. Отправлено суммарно — **69 244**. Одни и те же страницы уехали на сервер **больше трёх раз**.

Причина одна: **модель не помнит ничего.** Помнит твой массив `messages`, и ты пересылаешь его целиком на каждом шаге.

```
input  69244 × $2/M  = $0.1385   ← 84%
output  2677 × $10/M = $0.0268
```

В слайсе 1 output был 99% счёта. Здесь input 84%. **Полный разворот за один слайс.**

> Где лежат деньги — определяет архитектура, а не модель. Поэтому меряют, а не догадываются.

## Что стало лучше

Три основателя со ссылкой на `/about` вместо одного с выдуманной биографией. Тринадцать настоящих вакансий с точными названиями и локациями. Раунды, поглощения Mergent и Briefer, 3 млн пользователей, YC W23 — всё с источниками.

И твой агент нашёл `Backend Engineer (MTA), Trust & Safety` там, где мой ручной ресёрч часом раньше дал `Core Sending`. Страница обновилась — **инструмент оказался свежее заметок**.

## Что сломалось

`resend.com/careers/product-engineer` → 63 символа. `jobs.ashbyhq.com/resend` → 58. Это **client-rendered SPA**: контент рисует JavaScript, а твой `fetchText` умеет только срезать теги регуляркой. Описания отдельных вакансий так не достать.

# Слайс 3 — prompt caching

## Сначала теория: attention

Для каждого токена модель считает три вектора:

- **K (key)** — бирка: «про что я, чем полезен».
- **V (value)** — фактическое содержимое, что этот токен передаёт дальше.
- **Q (query)** — запрос текущего токена: «что я сейчас ищу».

Q сравнивается со **всеми K** → получаются веса релевантности → этими весами взвешиваются **V**. Q ищет, K отвечает за находимость, V переносит смысл.

## Почему кэшируют K и V, но не Q

**K и V токена зависят только от него самого и от того, что было ДО него.** От будущего — нет. Токен 500 уже надел бирку; что бы ни пришло на позиции 800, его K и V не изменятся никогда. Значит их можно посчитать один раз и хранить.

**Q нужен ровно один раз** — в момент обработки своего токена. Спросил и выбросил. Отсюда название **KV cache**, а не QKV.

**Отсюда же префиксность.** Поменяй токен на позиции 5 — все, кто после, находятся в другом контексте, их K/V другие. До пятого не затронуто. Кэш префиксный не по дизайну, а потому что математика не оставляет вариантов.

Общий закон, который ты применяешь каждый день:

> Кэшировать можно ровно то, что зависит **только от прошлого**.

`useMemo` — потому что результат зависит только от deps. Vite — потому что модуль зависит только от файла и его зависимостей. Здесь K/V — чистая функция от префикса.

## KV cache vs prompt caching

```
внутри одного запроса:   автоматически, бесплатно, всегда
между запросами:         выброшено ← сюда бьёт prompt caching
```

Внутри запроса модель и так не пересчитывает прошлое. Но состояние живёт **ровно один запрос**: ответ отдан, соединение закрылось, состояние выброшено.

Prompt caching — это «не выбрасывай, подержи пять минут». **Механизм тот же, меняется область жизни.**

Держать стоит им памяти, поэтому тариф тройной:

```
обычный input   1.00x
запись в кэш    1.25x   ← платишь один раз
чтение из кэша  0.10x   ← в десять раз дешевле
```

## Что делает твой код

`cache_control` — **чистое поле API**, обычный JSON. Ни SDK, ни TypeScript ни при чём.

```json
{ "type": "text", "text": "...", "cache_control": { "type": "ephemeral" } }
```

`moveBreakpoint` снимает пометку отовсюду и ставит на последний блок последнего сообщения. Пометок разрешено максимум четыре, поэтому старые надо стирать. Метка на `system` кэширует ещё и tools — порядок в промпте tools → system → messages.

**`ephemeral`** = «подержим, но не обещаем». Около пяти минут, каждое попадание продлевает. **Best-effort:** могут выселить раньше без всякой ошибки. Отсюда правило: **код обязан работать одинаково при нуле попаданий.** Кэш — оптимизация цены, а не часть логики.

Минимум ~1024 токена. Меньше — не кэшируется, поэтому у тебя на первом шаге `cache+ 0`.

## Твои числа

```
[step 1] new 712  cache+ 0      cache→ 0
[step 2] new   2  cache+ 10589  cache→ 0
[step 3] new   2  cache+ 7564   cache→ 10589
[step 4] new   2  cache+ 924    cache→ 18153
```

Свежий вход рухнул **712 → 2**. `new` — это токены, не покрытые ни записью, ни чтением; пометка в самом конце, поэтому непокрытым остаётся технический хвостик.

```
без кэша $0.12199
с кэшем  $0.07980
                    1.53x
```

**Важно про методологию.** Соблазн сравнить с слайсом 2 ($0.165) и написать «в два раза». Нельзя: тот прогон был на пяти шагах, этот на четырёх, агент каждый раз ходит по разным страницам. Сравнение двух прогонов недетерминированного агента меряет **маршрут**, а не оптимизацию. Валидно только `with` против `without` **внутри одного прогона** — и ты построил себе корректный A/B случайно, когда написал `report()`.

## Где деньги теперь

```
cache write  19077 × $2.50/M = $0.0477   60%
output        2492 × $10/M   = $0.0249   31%
cache read   28742 × $0.20/M = $0.0057    7%
new            718 × $2/M    = $0.0014    2%
```

Чтение почти бесплатное — ты вылечил пересылку. Осталась **запись: 60% счёта**. И кэшем это не лечится в принципе: ты суёшь в контекст двадцатикилознаковые простыни, и их приходится записывать по 1.25x.

## Заодно починено

`maxRetries: 5` и явный таймаут — после того как `APIConnectionTimeoutError` убил прогон на пятом шаге, потеряв четыре шага работы. И отчёт переехал на `process.on("exit")`, поэтому печатается **и при падении**.

> Инструментация, которая работает только на счастливом пути, бесполезна ровно тогда, когда нужна.

# Слайс 4 — дистилляция дешёвой моделью

## Что делает

Между `fetchText` и укладкой в `messages` встаёт Haiku: перемалывает сырую страницу в выжимку, и **дорогая модель видит только выжимку**.

```ts
async function distill(url: string, raw: string) {
  if (raw.startsWith("ERROR:") || raw.length < 800) return raw;
  const res = await client.messages.create({
    model: HAIKU,          // $1 / $5 против $2 / $10
    max_tokens: 600,
    system: "Extract only what matters for a job interview... compact bullet list...",
    messages: [{ role: "user", content: `URL: ${url}\n\n${raw}` }],
  });
  ...
}
```

## Почему это работает

Арифметика, ради которой всё:

> Haiku платит за страницу **один раз**. Sonnet платил бы за неё **запись в кэш плюс чтение на каждом следующем шаге**.

Пять тысяч токенов через Haiku — полцента. Те же пять тысяч в контексте Sonnet — запись по 1.25x, а потом чтение на каждом из оставшихся шагов. Ты меняешь **много раз дорого** на **один раз дёшево**.

Из 15 339 символов главной страницы Resend модели нужно от силы пятьсот.

## Какие это концепты

**#26, роутинг моделей.** Не «везде ставим самую умную», а «каждой задаче свой класс». Перемалывание текста — задача для Haiku, синтез досье — для Sonnet. На собесе «первое, что я проверяю при скачке costs — какая модель на каком шаге» звучит как опыт, а не как статья.

**Четвёртая ступень лестницы, map-reduce.** Режем на части, обрабатываем каждую независимо, собираем. Ты только что дошёл до неё не из оглавления, а потому что упёрся.

## Что мерить

**Колонка `raw → distilled`.** Ожидай что-то вроде `15339 → 900`.

**`cache+` должен рухнуть.** Это те самые 60%.

**И — обязательно — потерю информации.** Haiku мог выбросить точные названия вакансий, локации, имена. Если в досье пропали детали, которые были в прошлом прогоне, виноват промпт дистилляции, а не идея.

Вот это и есть настоящий инженерный вопрос слайса:

> Ты вводишь потерю информации в обмен на деньги. **Померь, сколько потерял.**

Не «стало дешевле» — а «стало дешевле в N раз, и вот что за это отдано».
