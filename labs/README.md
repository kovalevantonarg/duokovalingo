# drill-labs

Практика к билетам из duokovalingo. Каждая лаба: маленькая задача на TS + готовые падающие тесты
на edge-кейсы (пограничные случаи), которые реально ломают LLM-продукты в проде. Твоя работа: сделать тесты зелёными.

```bash
npm i
npm run watch -- 01        # одна лаба в режиме слежения
npm test                   # все лабы против твоего кода в src/
npm run test:solutions     # те же тесты против эталона в solutions/
```

Лабы встроены в duokovalingo (вкладка «Разборы» → «Лабы»): там тот же код и те же тесты запускаются прямо в браузере, прогресс синхронизируется. После правки лабы пересобери данные для приложения из корня репозитория: `node scripts/build-labs.mjs`.

Сеть и API-ключ не нужны: модель в тестах скриптованная (`shared/fake-client.ts`).
Так агентов и тестируют в компаниях: детерминированно и бесплатно. Живые эксперименты с API описаны в README каждой лабы и необязательны.

## Как устроена лаба

В каждой папке лабы: `README.md` (задача и пограничные случаи), `WALKTHROUGH.md` (разбор: решение собирается по шагам), тесты лабы и папка `repeat/` с похожей задачей на повторение (свой README, тесты, заготовка в `src/<имя>-2.ts`, эталон в `solutions/`). В приложении это три шага: разбор, повторение, интервью.

## Как проходить лабу

1. Прочитай README лабы и тесты. Тесты и есть спецификация.
2. Пиши в `src/`. В `solutions/` не смотри, пока не позеленел или честно не застрял минут на 40.
3. После зелёного: ответь вслух на прод-сценарий из README, как на интервью, 60–90 секунд.
4. В drill после этого билет можно оценивать голосом заново: ответ теперь опирается на код, который ты написал.
