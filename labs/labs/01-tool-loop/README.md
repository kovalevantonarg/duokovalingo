# 01. Tool loop

**Билеты:** 7 Tool use, 8 Стоп-условия и ошибки, 14 ReAct, 3 Экономика токенов, 38 Граница runtime, 33 Отмена.

**Задача:** `runAgent` в `src/tool-loop.ts`. Модель возвращает блоки `tool_use`, исполняешь их ты, результат уходит обратно как `tool_result`, и так по кругу, пока модель не закончит или не сработает одно из стоп-условий.

## Edge-кейсы и почему они важны в проде

- **Ассистентское сообщение уходит обратно целиком.** Выкинешь текст перед `tool_use` или переставишь блоки, и модель теряет собственные рассуждения; а без `tool_use` в истории API вернёт 400 на `tool_result`.
- **Параллельные вызовы.** Модель может попросить два инструмента в одном ответе. Все `tool_result` идут в одном user-сообщении и в том же порядке. Разложишь по разным сообщениям, получишь 400.
- **Ошибка инструмента это данные, а не исключение.** 404 от базы, таймаут, неизвестное имя, кривые аргументы: всё становится `tool_result` с `is_error: true`. Модель умеет исправиться («нет такого заказа, уточню у пользователя»), если ей сказать, что пошло не так. Упавший цикл ничего не исправит.
- **Аргументы валидируются, хотя у инструмента есть схема** (KILL билета 38). Схема в запросе это подсказка модели, а не гарантия. `{"order_id": "W1"}` без решётки прилетит обязательно.
- **`stop_reason: max_tokens` посреди `tool_use`.** JSON аргументов мог оборваться. Исполнять такой вызов нельзя: в лучшем случае упадёт парсинг, в худшем отменишь не тот заказ. То же с `model_context_window_exceeded`.
- **Потолок ходов и детект повтора.** Зациклившийся агент жжёт деньги молча. Потолок ловит долгие петли, детект повтора ловит тупые (тот же вызов с теми же аргументами).
- **Usage по всем ходам.** В агенте input растёт каждый ход, потому что история пересылается целиком. Вот откуда «в агенте input стал 84% счёта» из билета 3.
- **Отмена.** Пользователь нажал Stop: дальше модель не вызывается, а `signal` доходит до инструментов, чтобы и они остановили свои запросы.
