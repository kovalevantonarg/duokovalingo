# Повторение: агент поддержки провайдера с бюджетом

**Задача:** `runSupportAgent` в `src/tool-loop-2.ts`. Агент поддержки интернет-провайдера проверяет линию клиента (`check_line`) и открывает заявку на мастера (`open_ticket`). Цикл тот же: модель просит инструменты, ты их исполняешь и возвращаешь `tool_result`, пока модель не закончит или не сработает стоп. Но деньги здесь считаются явно: у каждого хода есть цена, и агент обязан остановиться, когда бюджет кончился.

Чем отличается от лабы: инструменты приходят массивом `SupportTool[]` с полем `name` (значит, имена могут повториться, и это надо поймать до первого вызова модели); вместо `usage` ты считаешь доллары по `pricing`; есть стоп по `budgetUsd`; после каждого хода вызывается `onStep` с отчётом. Детекта повтора и отмены здесь нет, зато поля называются по-другому (`schema`, `handler`, `history`, `transcript`, `status`), так что скопировать лабу не выйдет.

## Что проверяют тесты

- **Запрос** инструменты из массива уходят в `tools` в том же порядке, `input_schema` собрана из zod, `system` передан.
- **Happy path** ассистентское сообщение возвращается в историю целиком, `tool_result` с тем же id, объект сериализован в JSON, `status: 'done'`.
- **Конфигурация** два инструмента с одним `name` дают исключение до первого вызова модели; входная `history` не мутируется.
- **Параллельные вызовы** все результаты в одном user-сообщении, в порядке вызовов, даже если первый отвечает дольше.
- **Ошибки как данные** неизвестное имя, аргументы не прошли zod (handler не вызван), handler бросил исключение: всё это `is_error: true`, цикл живёт.
- **Обрезка и отказ** `max_tokens` даёт `truncated` без исполнения инструментов, `refusal` даёт `refused`.
- **Потолок и бюджет** `maxTurns` даёт `turn_limit`; когда потраченное дошло до `budgetUsd`, следующий вызов модели не делается и `status: 'over_budget'`.
- **onStep** один вызов на ход: номер хода, `stop_reason`, какие инструменты исполнены и какие упали, траты нарастающим итогом.

## Подсказки

- Структура повторяет шаги 2, 3 и 5 разбора: состояние, ход модели, `switch` по `stop_reason`, `Promise.all` по вызовам. Новое только в шагах до цикла (уникальность имён) и в стоп-проверках.
- Сделай `Map` имя → инструмент до цикла и бросай ошибку на повторе имени. Стоимость хода считай по `res.usage`: `(input_tokens * inputPerMTok + output_tokens * outputPerMTok) / 1e6`. Проверку бюджета ставь рядом с проверкой `maxTurns`, в начале круга, до вызова модели.
- `onStep` зови после того, как результаты инструментов готовы: `calls` это `uses.map((u, i) => ({ name: u.name, isError: results[i]!.is_error === true }))`. Для хода без инструментов (конец, обрезка, отказ) зови его с пустым `calls` перед `return`.
