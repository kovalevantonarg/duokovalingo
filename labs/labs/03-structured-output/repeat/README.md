# Повторение: счёт от поставщика

**Задача:** в `src/extract-2.ts` две вещи. Первая: `invoiceRules`, бизнес-правила счёта поверх готовой схемы `InvoiceDraft` (срок оплаты позже даты счёта, сумма позиций равна `total`). Вторая: `extractInvoice`, который достаёт счёт из текста письма или OCR через принудительный вызов инструмента `record_invoice` и чинит ошибки модели обратной связью. История: бухгалтерия кафе получает счета от поставщиков в почту, а код должен заводить их в учёт без ручного ввода.

Отличия от лабы. Схема теперь не приходит снаружи, правила пишешь ты, причём правила связывают несколько полей, поэтому это `superRefine` на объекте с явным `path`. Ошибки бывают во вложенных позициях, и модели нужен полный путь вроде `items.1.quantity`. Деньги во float надо сравнивать аккуратно. Ошибка в конце несёт не одну строку, а массив `issues` последней попытки.

## Что проверяют тесты

- **Правильный счёт** проходит схему `Invoice` целиком.
- **due_at раньше issued_at** даёт ошибку ровно на поле `due_at`.
- **total не равен сумме позиций** даёт ошибку на поле `total`, и в тексте есть настоящая сумма.
- **3 × 0.1 при total 0.3** проходит: float не ломает сравнение денег.
- **Запрос** содержит один инструмент `record_invoice` со схемой счёта, `tool_choice` на него и текст документа первым сообщением.
- **Ошибка валидации** уходит модели как `tool_result` с `is_error` и полным путём поля, вторая попытка успешна.
- **Потолок попыток**: после `maxAttempts` бросается `InvoiceExtractionError` с `attempts` и `issues`, лишних вызовов нет; то же, если модель всё время отвечает текстом.
- **Ответ текстом** вызывает просьбу обычным user-сообщением без `tool_result`, а `max_tokens` сразу даёт `InvoiceTruncatedError`.

## Подсказки

- Цикл `extractInvoice` повторяет шаги 1-6 разбора почти один в один; новое здесь только `invoiceRules` и массив `issues`.
- В `invoiceRules` каждая проблема это `ctx.addIssue({ code: 'custom', path: ['total'], message })`. Сумму считай через `reduce` по `quantity * unit_price`, сравнивай в центах через `Math.round(x * 100)`.
- Строка ошибки для модели: для каждого `issue` склей `i.path.join('.')` (пустой путь замени на `(root)`), двоеточие и `i.message`. Путь `['items', 1, 'quantity']` после `join('.')` и есть `items.1.quantity`. Для ответа текстом положи в `issues` одну строку с именем `record_invoice`, а после цикла брось `new InvoiceExtractionError(message, maxAttempts, issues)`.
