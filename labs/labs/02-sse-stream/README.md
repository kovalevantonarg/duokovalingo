# 02. SSE stream

**Билеты:** 11 Streaming: SSE и ReadableStream, 50 Стриминг: SSE, WebSocket, fetch, 20 Дизайн streaming chat UI.

**Задача:** два слоя в `src/sse.ts`. `parseSSE` превращает сырые байты в события по спецификации SSE (Server-Sent Events: HTTP-ответ, который сервер не закрывает и дописывает строками). `collectMessage` собирает из событий Anthropic текст, вызовы инструментов и `stop_reason`.

Почему не `EventSource`: он умеет только GET без заголовков, а тебе нужен POST с историей и `Authorization`. Поэтому `fetch` и чтение `response.body` руками, то есть ровно этот код.

## Edge-кейсы

- **Сеть режет байты где угодно**, не по строкам и не по событиям. Нужен буфер для хвоста.
- **Кириллица пополам.** Русская буква это 2 байта UTF-8. Без `{ stream: true }` у `TextDecoder` на стыке чанков вылезет `�`, и на демо это всплывёт ровно на русском тексте (KILL билета 11).
- **`\r` в конце одного чанка и `\n` в начале следующего** это один перевод строки, а не два. Иначе получишь лишнюю пустую строку и разрежешь событие.
- **Комментарии `:`** прокси шлют, чтобы держать соединение живым. Игнорировать.
- **Аргументы инструмента приходят кусками** (`input_json_delta`), каждый кусок по отдельности невалидный JSON. Парсить только на `content_block_stop`. Пустая строка это `{}`.
- **`event: error` посреди потока** (например, `overloaded_error`) приходит уже после HTTP 200. Обычной проверкой статуса не поймаешь. Полученный текст терять нельзя.
- **Обрыв без `message_stop`.** Ошибки нет, поток просто кончился. Если не проверять `complete`, UI покажет полуответ как полный.

## Живой эксперимент (по желанию)

```ts
const res = await fetch('https://api.anthropic.com/v1/messages', {
  method: 'POST',
  headers: { 'x-api-key': process.env.ANTHROPIC_API_KEY!, 'anthropic-version': '2023-06-01', 'content-type': 'application/json' },
  body: JSON.stringify({ model: 'claude-haiku-5-5', max_tokens: 300, stream: true, messages: [{ role: 'user', content: 'Расскажи про SSE в трёх абзацах' }] }),
})
console.log(await collectMessage(res.body!))
```
Замерь время до первого `text_delta` (TTFT, time to first token) против времени до `message_stop`. Эти две цифры и есть ответ на вопрос «зачем вообще стриминг».
