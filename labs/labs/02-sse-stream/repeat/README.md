# Повторение: NDJSON-поток с OpenAI-чанками

**Задача:** в компании стоит внутренний LLM-шлюз (gateway: прокси перед моделями). Он ходит в OpenAI-совместимые модели и отдаёт ответ клиенту как NDJSON (newline-delimited JSON: одна JSON-строка на объект, как у ollama). Каждая строка это чанк в стиле OpenAI Chat Completions: текст в `choices[0].delta.content`, вызовы инструментов в `choices[0].delta.tool_calls`. Поток кончается строкой `{"done":true}`, а при сбое модели посреди ответа шлюз пишет строку `{"error":{"code":"…","message":"…"}}`. Реализуй в `src/chat-stream-2.ts` два слоя: `parseNDJSON` (байты → объекты) и `collectChat` (объекты → `ChatResult`).

Навыки те же, что в лабе, поверхность другая. Полей `event:`/`data:` нет, разделитель только `\n`, зато последняя строка может прийти без `\n`, и её надо отдать (в SSE её бы выбросили). Нет отдельного `content_block_stop` на каждый вызов: у каждого куска аргументов есть `index`, `id` и `name` приходят только в первом куске, а собрать аргументы целиком можно, только когда пришёл `finish_reason`.

## Что проверяют тесты

- **Строки в объекты** несколько строк в одном чанке дают по объекту на строку, JSON, разрезанный между чанками, собирается.
- **Кириллица пополам** чанк режет русскую букву посреди UTF-8, текст остаётся целым.
- **CRLF и пустые строки** `\r` в конце чанка и `\n` в начале следующего не дают лишних объектов, пустые строки пропускаются.
- **Последняя строка без \n** в конце потока тоже объект.
- **Битая строка** даёт `Error` с номером строки в сообщении.
- **Текст и finish_reason** склеиваются из чанков, `{"done":true}` ставит `complete: true`, чанк с пустым `choices` не мешает.
- **Инструменты** аргументы кусками по `index`, два вызова вперемешку, пустые аргументы это `{}`, порядок по `index`.
- **Обрывы и ошибки** строка с `error` сохраняет уже полученный текст, поток без `{"done":true}` даёт `complete: false`, обрыв посреди аргументов не роняет `JSON.parse` и не отдаёт полувызов.

## Подсказки

- `parseNDJSON` повторяет шаг 1 разбора: reader, `TextDecoder` с `{ stream: true }`, буфер для хвоста. `collectChat` повторяет шаги 5-7: один результат, который дописываешь по мере событий, и `return` на ошибке.
- Режь буфер только по `\n`, а `\r` в конце уже вырезанной строки срезай. Тогда `\r` на стыке чанков решается сам, без трюка с `final` из шага 3. После цикла не забудь `decoder.decode()` и непустой хвост `buf`.
- В `collectChat` держи `Map<number, { id: string; name: string; args: string }>` по `tc.index`: `id` и `name` записывай, только если они есть в куске, `arguments` дописывай. На `finish_reason` собери `toolCalls` из Map, отсортировав по index, с `args: c.args ? JSON.parse(c.args) : {}`. До `finish_reason` ничего не парси, тогда обрыв посреди аргументов просто оставит `toolCalls: []`.
